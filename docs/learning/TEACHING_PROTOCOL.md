# 教学协议

## 单次聊天边界

- 一个聊天只负责一个阶段。
- 一个阶段可以包含多课，但一次只推进一课。
- 如果用户在当前聊天要求另一个阶段，先提示应新建聊天；除非用户明确要求切换。
- 不提前创建尚未学习的课程代码。

## 每课固定流程

1. **复习**：检查上一课答案或代码，不重复整章内容。
2. **目标**：用一句话说明本课唯一目标和暂不学习的内容。
3. **心智模型**：解释数据如何流动、程序实际做了什么。
4. **最小实现**：只创建或修改本课对应的一个 `.py` 文件。
5. **验证**：运行安全、必要的命令，展示可观察结果。
6. **用户练习**：要求用户运行、解释或做一个小改动。
7. **验收问题**：通常 2–3 个，验证理解而不是背语法。
8. **记录进度**：通过后更新 `PROGRESS.md`，再进入下一课。

## 代码规则

- 课程文件放在 `lessons/`，文件名必须与阶段大纲一致。
- 初期允许少量重复，优先保证单文件可读；到整合阶段再抽取模块。
- 每个文件尽量保持在 20–80 行，超过时先判断是否混入多个概念。
- 示例必须可运行，并且输出要能帮助观察本课概念。
- 所有命令使用 `uv run`、`uv add`、`uv sync` 等 uv 工作流。

## 安全规则

- API Key 不进入代码、Markdown 示例中的真实值、终端输出或聊天回复。
- `.env` 必须被 `.gitignore` 忽略；Codex 不读取或回显真实内容。
- 有外部写入、删除、付款、发消息等副作用的工具必须加入审批课程。
- Agent Loop 必须有最大轮次、超时、错误处理和停止条件。

## 完成判定

一课完成需要同时满足：

- 对应文件存在且能够运行，或该课约定的测试通过；
- 用户完成指定练习；
- 用户能回答本课核心问题；
- `PROGRESS.md` 已更新。

一个阶段完成需要该阶段所有必修课完成，并通过阶段作品和阶段验收。
